# bug-fg-php-dependencies

This repository shows a bug with multiple dependencies added to FunctionGraph.

Following steps shows how to reproduce the issue:

## Step 1: Create dependency files

In root run:

```bash
make create_dependencies
```

This will create following zip files containing dependencies:

- ```dependency-brick-date-time/vendor.zip```
- ```dependency-guzzle/vendor.zip```

## Step 2: Install dependencies to FunctionGraph

In **FunctionGraph console** -> **Functions** -> **Dependencies**:

Create dependency for Brick date time using following values:
- Name: **php-brick-date-time**
- Runtime: **PHP 8.3**
- Code Entry Mode: **Upload ZIP**
- Upload file: **dependency-brick-date-time/vendor.zip**

Create Dependency for Guzzle using following values:
- Name: **php-guzzle**
- Runtime: **PHP 8.3**
- Code Entry Mode: **Upload ZIP**
- Upload file: **dependency-guzzle/vendor.zip**

## Step 3: Create FunctionGraph function

In **FunctionGraph console** -> **Dashboard** -> **Create Function**.

Create new function with following values:

- Create with: **Create from scratch**
- Function Type: **Event Function**
- Region: **eu-de**
- Function Name: **bug-php-multiple-deps**
- Runtime: **PHP 8.3**

In code tab paste code from ```fg/index.php```

In **Dependencies** add following **Private** dependencies with **version 1**:

- Name: **php-guzzle**
- Name: **php-brick-date-time**

## Step 4: Configure Function
In tab **Configuration** -> **Basic Settings**
set Handler to **index.handler**


## Test 1 - Show error

Click **Test** and use any test event.

Following error will occur:

```json
{
    "errorMessage": "function invocation exception, error: Class \"GuzzleHttp\\Client\" not found",
    "errorType": "EXCEPTION",
    "stackTrace": {
        "file": "/index.php",
        "line": 53
    }
}
```

## Test 2 - List dependencies
Change handler name to **index.ListDependenciesHandler** and execute **Test** again.

This will list dependencies in folder ```vendor```:

```
/opt/function/code/vendor/composer
/opt/function/code/vendor/autoload.php
/opt/function/code/vendor/brick
/opt/function/code/vendor/symfony
/opt/function/code/vendor/.
/opt/function/code/vendor/..
/opt/function/code/vendor/psr
/opt/function/code/vendor/ralouphie
/opt/function/code/vendor/guzzlehttp
```

-> This shows that configured dependencies are copied correctly to vendor folder!


## Test 3 - check autoload_psr4.php file

Change handler name to **index.DisplayFileHandler** and execute **Test** again.

This will display content of ```/vendor/composer/autoload_psr4.php```

```php
<?php
// autoload_psr4.php @generated by Composer
$vendorDir = dirname(__DIR__);
$baseDir = dirname($vendorDir);
return array(
'Brick\\DateTime\\' => array($vendorDir . '/brick/date-time/src'),
);
```

The array in this file should also include:

```php
'GuzzleHttp\\Psr7\\' => array($vendorDir . '/guzzlehttp/psr7/src'),
'GuzzleHttp\\Promise\\' => array($vendorDir . '/guzzlehttp/promises/src'),
'GuzzleHttp\\' => array($vendorDir . '/guzzlehttp/guzzle/src'),
```

## Problem

It seems that 

```bash 
composer update
```

is not run correctly if multiple dependencies are added to FunctionGraph
